## 1. 这个项目是做什么的

给定一张海滩/湿地照片，找出照片里所有的鸟，并用矩形框把每只鸟框出来。

- 输入：一张 512×512 的彩色图片（RGB）。
- 输出：若干个框，每个框包含 `[左上角x, 左上角y, 右下角x, 右下角y, 置信度]`。
- 数据集：Kaggle 上的 **Beach Bird Detection Dataset**，共 1,900 张图、12,024 只鸟，
  官方已经切分成 train / val / test 三部分。

项目实现了三大类方法，并用**完全相同**的评估代码比较它们：

| 类别 | 方法 | 一句话原理 |
|---|---|---|
| 非学习（传统图像处理） | 全局 Otsu、多尺度黑帽/顶帽、分水岭 | 靠颜色/对比度/形状规则找"像鸟的斑块" |
| 机器学习 | HOG / HOG+LBP + SVM / 随机森林 + 滑窗 | 人工设计特征，训练一个分类器判断"窗口里是不是鸟" |
| 深度学习 | YOLOv8n / YOLOv8s / YOLO11n，不同分辨率与增强 | 神经网络直接学习"哪里有什么" |

除此之外还做了两类**推理后处理**实验：

- **TTA（测试时增强）**：把图片翻转/缩放后多预测几次再合并，通常能小幅提升精度。
- **切图推理（tiled inference）**：把 512×512 切成 2×2 有重叠的小块，再放大检测，
  专门用来找回很小的鸟。

## 2. 先认识几个最基本的概念

这一节解释后面会反复出现的词。**看不懂公式没关系，记住直觉即可。**

### 2.1 边界框（bounding box，简称 box）

用一个矩形表示"鸟在哪里"。本项目统一用左上角 `(x1, y1)` 和右下角 `(x2, y2)` 表示，
写作 `[x1, y1, x2, y2]`。像素坐标原点在图片左上角，x 向右，y 向下。

### 2.2 IoU（交并比，Intersection over Union）

衡量"预测框"和"真实框"重合多少：

```
IoU = 两个框重叠的面积 ÷ 两个框合起来的总面积
```

- 完全重合：IoU = 1
- 完全不相交：IoU = 0
- 通常 IoU ≥ 0.5 就认为"框对了"。

> 为什么用 IoU 而不是"中心点距离"？因为 IoU 同时惩罚位置偏差和大小偏差。
> 一个把整片沙滩都框进去的框，中心点可能很准，但 IoU 很低。

### 2.3 TP / FP / FN

| 缩写 | 全称 | 直觉 |
|---|---|---|
| TP | True Positive | 真的鸟，被正确框出来了 |
| FP | False Positive | 本来不是鸟（石头/浪花），却被框了（**误检**） |
| FN | False Negative | 真的有鸟，但没被框出来（**漏检**） |

判断规则：预测框与某个真实框 IoU ≥ 阈值（本项目默认 0.5），且该真实框还没被别的预测框占用，
就算 TP；否则算 FP。没被任何预测框匹配的真实框算 FN。

### 2.4 Precision / Recall / F1

```
Precision（精确率）= TP / (TP + FP)   → 报出来的框里，有多少是真的
Recall（召回率）  = TP / (TP + FN)   → 真实的鸟里，有多少被找到了
F1 = 2 × Precision × Recall / (Precision + Recall)
```

两者通常此消彼长：

- 把置信度阈值调**低** → 框更多 → 召回率↑、精确率↓（宁可错杀）
- 把置信度阈值调**高** → 框更少 → 精确率↑、召回率↓（宁可放过）

F1 是两者的调和平均，用来选一个"综合最好"的阈值。

### 2.5 置信度（confidence / score）

模型对"这个框里是鸟"的把握，通常 0~1（HOG 的 SVM 输出可能是任意实数，但排序含义相同）。
**mAP 不需要你提前定阈值**：它会把所有框按置信度从高到低排序，再看整条曲线。

### 2.6 AP 与 mAP@0.5

把置信度从高到低排列，逐个判断 TP/FP，可以得到一条 **Precision-Recall 曲线**。
AP（Average Precision）就是这条曲线下的面积，范围 0~1，越大越好。

- `AP@0.5`：只要求 IoU ≥ 0.5 就算对。
- `AP@0.75`：要求更严格的定位（IoU ≥ 0.75）。
- `AP@0.5:0.95`：在 0.50, 0.55, …, 0.95 十个阈值上取平均，是 COCO 的主指标，最难。
- `mAP` 的 "m" 是 mean（对类别平均）。本数据集只有 `bird` 一类，所以 **mAP@0.5 = AP@0.5**。

### 2.7 NMS（非极大值抑制）

同一只鸟会被很多相邻窗口/锚点检测到，产生一堆重叠框。
NMS 的做法：按分数从高到低，保留最高分的框，把与它 IoU 超过阈值的其他框删掉，重复。

- NMS 阈值调**小**（如 0.3）：删得狠，密集鸟群容易被误删。
- NMS 阈值调**大**（如 0.6）：保留多，密集场景召回高，但重复框多。

### 2.8 滑窗（sliding window）

HOG+SVM 使用的方法：拿一个固定大小的窗口（如 64×64），在图片上每隔 `stride` 像素滑动一次，
每个位置都问分类器"这是不是鸟"。

- 窗口**大**：能看见更多上下文，但小目标在窗口里占比太小，容易漏。
- 窗口**小**：对小目标友好，但大鸟装不下。
- 所以要同时用多个尺寸（多尺度）。

### 2.9 数据增强（data augmentation）

训练时对图片做随机变换（翻转、缩放、变色、拼图），让模型见过更多"变形"，
从而在测试时更稳健。**只在训练时做，验证/测试时绝不做随机变换。**

### 2.10 过拟合与欠拟合

- **欠拟合**：训练集和验证集都差 → 模型太简单/训练不够 → 增加轮数、换大模型。
- **过拟合**：训练集很好、验证集明显差 → 模型在"背答案" → 加数据增强、早停、减小模型。

## 4. 安装环境（Windows 一步步来）

### 4.1 安装 Python

要求 **Python 3.10 ~ 3.12**。安装时勾选 "Add Python to PATH"。
验证：

```powershell
python --version
```

### 4.2 创建虚拟环境

虚拟环境相当于给这个项目单独的"工具箱"，不会污染系统 Python。

```powershell
cd D:\你的路径\beach_bird_project
python -m venv .venv
.\.venv\Scripts\activate
```

激活后命令行前面会出现 `(.venv)`。

> 如果使用 `uv`（更快）：
> ```powershell
> uv venv --python 3.11 .venv
> .\.venv\Scripts\activate
> ```

### 4.3 安装 PyTorch

先确认有没有 NVIDIA 显卡：

```powershell
nvidia-smi
```

**有 NVIDIA 显卡**：去 <https://pytorch.org/get-started/locally/> 选对应 CUDA 版本的命令。例如 CUDA 12.6：

```powershell
pip install torch torchvision --index-url https://download.pytorch.org/whl/cu126
```

**没有显卡（只用 CPU）**：

```powershell
pip install torch torchvision
```

CPU 也能跑，但 YOLO 训练会慢 10~30 倍。建议减少 `--epochs` 或用小模型。

验证：

```powershell
python -c "import torch; print(torch.__version__, torch.cuda.is_available())"
```

输出 `True` 表示 GPU 可用。

### 4.4 安装其余依赖

```powershell
pip install -r requirements.txt
```

**重要坑**：OpenCV 5.x 删除了 `cv2.HOGDescriptor`，本项目 HOG 部分会直接报错。
`requirements.txt` 已限制 `opencv-python<5`。如果之前装过 5.x，执行：

```powershell
pip install "opencv-python==4.12.0.88"
```

验证：

```powershell
python -c "import cv2; print(cv2.__version__, hasattr(cv2,'HOGDescriptor'))"
```

应输出 `4.x True`。

pip install kagglehub
python -c "import kagglehub; print(kagglehub.dataset_download('liugalhigh/beach-bird'))"

### 标签格式说明

每张图对应一个同名 `.txt`，每行一只鸟：

```
class_id  x_center  y_center  width  height
```

数值都除以了图片宽高，范围 0~1。例如 `0 0.5 0.5 0.1 0.2` 表示图片正中央、宽 10%、高 20% 的鸟。
没有鸟的图片对应一个**空 txt**（这是负样本，很重要，不能删）。

## 7. 三种方法是怎么工作的

### 7.1 传统图像处理（`src/classical.py`）

不训练任何模型，完全靠规则。三个变体：

#### (a) 全局 Otsu（`global_otsu`）

1. 转灰度；
2. 用 Otsu 算法自动选一个全局阈值，把"比背景暗"的像素变成白色；
3. 形态学开/闭运算去掉噪点；
4. 每个连通的白色区域的外接矩形就是一个候选框；
5. 按面积、长宽比、填充率过滤。

**问题**：它假设"鸟一定比背景暗"，而且整张图共用一个阈值。
白色海鸥、阴影、深色礁石都会出错。

#### (b) 多尺度黑帽/顶帽（`multiscale_blackhat`）

- **黑帽（black-hat）** = 闭运算结果 − 原图 → 突出"比周围暗的小斑块"（深色鸟）。
- **顶帽（top-hat）** = 原图 − 开运算结果 → 突出"比周围亮的小斑块"（白色鸟）。
- 对每个尺寸的结构元素（7、11、17、25、35、51 像素）各算一次，取二者较大值。
- 每个尺度用 Otsu 选阈值，得到候选连通域，再按形状/尺寸过滤，最后跨尺度 NMS。

**为什么多尺度**：鸟在图片里大小不一（本项目框边长从 13 px 到 180 px）。
小结构元素只能看到小鸟，大结构元素才能看到大鸟。

#### (c) 黑帽 + 分水岭（`multiscale_blackhat_ws`）

密集鸟群里，几只鸟的白色区域会粘成一块。分水岭（watershed）用距离变换找"每只鸟的中心"，
把粘连区域切开。只在面积 2,500~12,000 px²、填充率较高的连通域上做，避免把礁石切碎。

**传统方法的共同弱点**：它不知道"鸟长什么样"，只知道"这里和周围不一样"。
浪花、礁石纹理、建筑边缘都满足这个条件，所以误检很多。这也是报告里重点分析的内容。

### 7.2 HOG + SVM 滑窗（`src/hog_svm.py`）

完整流程：

```
训练阶段：
  训练图片 ──裁 GT 框（外扩 1.3 倍）──> 正样本 patch（64×64）
           ──随机裁背景──────────────> 负样本 patch
           ──用第一版模型找高分误检────> 难负样本（hard negatives）
  所有 patch ──> HOG（+LBP）特征 ──> 标准化 ──> LinearSVC

测试阶段：
  图片 ──多尺度滑窗（32/48/64/96/128，步长 16）──> 每个窗口 resize 到 64×64
       ──> HOG 特征 ──> SVM 打分 ──> 阈值筛选 ──> NMS ──> 输出框
```

关键细节：

- **HOG** 把 64×64 窗口分成 8×8 的 cell，统计每个 cell 里梯度的方向直方图，
  再 2×2 个 cell 组成 block 做归一化。输出 1,764 维。它描述"边缘/纹理长什么样"。
- **LBP** 描述局部纹理的二进制模式，本项目中把图分成 4×4 网格，每格 10 维直方图，共 160 维。
- **难负样本挖掘**：先用随机负样本训练一版；拿它去训练集上跑，把"分数很高但其实不是鸟"的窗口
  收集起来，加入负样本再训练。这是 HOG 检测器提升精度的关键技巧。
- **尺度惩罚** `size_score_penalty`：大窗口看到的背景多，SVM 分数容易偏高，
  导致"一个大框把几只鸟全包进去"。用 `score − λ·log2(size/64)` 校正，
  再配合"包含关系剪枝"，优先保留贴合的小框。

**HOG 的优缺点**：

- 优点：不需要 GPU，训练快（几分钟），可解释性强，能清楚看到"特征工程"的作用。
- 缺点：滑窗计算量大；对很小/很密集的鸟不友好；手工特征无法区分"鸟"和"像鸟的石头"。

### 7.3 YOLO（深度学习）

YOLO 是 **one-stage** 检测器：一次前向传播，直接在特征图上预测每个位置的框和类别，
不需要像 Faster R-CNN 那样先产生候选区域（two-stage）。

本项目使用 Ultralytics 的实现，比较了：

| 实验名 | 模型 | 输入 | 数据增强 | 目的 |
|---|---|---|---|---|
| `yolov8n_plain` | YOLOv8n | 512 | 无 | 干净基线 |
| `yolov8n_aug` | YOLOv8n | 512 | 默认增强 | 看增强的收益 |
| `yolo11n_aug` | YOLO11n | 512 | 默认增强 | 看新架构 |
| `yolov8s_aug` | YOLOv8s | 512 | 默认增强 | 看模型容量 |
| `yolov8n_aug_960` | YOLOv8n | 960 | 默认增强 | 看输入分辨率（小目标） |

后处理实验（同一个 `yolov8n_aug` 权重）：

- `tta`：推理时做多尺度/翻转增强，再合并。
- `tile2`：2×2 切图，每块放大到 640 检测，合并后 NMS。

| 参数 | 作用 | 调大/调小会怎样 |
|---|---|---|

| 参数 | 含义 | 说明 |
|---|---|---|
| `--weights` | 权重路径 | 必填 |
| `--name` | 实验名 | 输出文件名 |
| `--split` | val/test/train | 最终测试用 test |
| `--imgsz` | 推理分辨率 | 可以和训练不同，例如训练 512、推理 640 |
| `--conf` | 置信度阈值 | 算 mAP 时设 **0.001**，让模型尽量多输出候选 |
| `--iou` | 模型内部 NMS IoU | 密集场景可调到 0.6~0.7 |
| `--max-det` | 每图最多保留多少框 | 密集图（130 只）要 ≥300 |

> mAP 会自己按置信度排序，不需要你提前卡阈值。如果这里设 0.25，低分但正确的框会被提前删掉，
> 导致 mAP 偏低。真正部署时才需要把 `conf` 调到 0.25~0.5 来减少误报。

## 9. 结果怎么看：指标解释

### 9.1 本项目实际结果（测试集，2026-11 运行）

| 方法 | AP@0.5 | AP@0.75 | F1 | 每图耗时 |
|---|---:|---:|---:|---:|
| Global Otsu | 0.016 | 0.004 | 0.071 | 9 ms |
| 多尺度黑帽/顶帽 | 0.021 | 0.003 | 0.096 | 75 ms |
| 黑帽 + 分水岭 | 0.017 | 0.002 | 0.091 | 88 ms |
| HOG + Linear SVM（纯滑窗） | 0.011 | 0.000 | 0.058 | 458 ms |
| HOG + SVM（候选框级联） | 0.015 | 0.001 | 0.074 | 72 ms |
| HOG+LBP + SVM（候选框级联） | 0.021 | 0.001 | 0.079 | 86 ms |
| HOG + Random Forest（候选框级联） | **0.022** | 0.001 | 0.076 | 75 ms |
| YOLOv8n（无增强） | 0.750 | 0.323 | 0.725 | 27 ms |
| YOLOv8n + 增强 | 0.871 | 0.458 | 0.835 | 23 ms |
| YOLO11n + 增强 | **0.876** | 0.459 | 0.836 | 25 ms |
| YOLOv8s + 增强 | 0.872 | 0.458 | 0.841 | 25 ms |
| YOLOv8n @960 | 0.806 | 0.418 | 0.773 | 18 ms |
| YOLOv8n + TTA | 0.860 | **0.470** | 0.822 | 32 ms |
| YOLOv8n + 2×2 切图 | 0.779 | 0.382 | 0.771 | 49 ms |

**结论**：

- 深度学习明显最好：YOLO 的 AP@0.5 约 0.87，手工特征方法只有 0.02 左右。
- 数据增强是 YOLO 最大的收益来源：0.750 → 0.871。
- HOG 的瓶颈在"候选框定位"，不在分类器：把滑窗换成传统候选框后，
  AP 从 0.011 升到 0.046（验证集），速度还快了 8 倍。
- TTA 主要改善定位（AP@0.75 0.458 → 0.470），对 AP@0.5 没有帮助。
- 把 512 放大到 960、或 2×2 切图，在本数据集上**没有提升**；切图还会严重伤害大目标
  （large AP 0.680 → 0.493）。这是一个很有价值的"负结果"：分辨率不是越高越好。

打开 `results/tables/main_results.csv`，各列含义：

| 列名 | 含义 | 越大越好？ |
|---|---|---|
| `AP@0.5` | IoU=0.5 时的平均精度，**作业要求的核心指标** | 是 |
| `AP@0.75` | 更严格定位要求下的 AP | 是 |
| `AP@0.5:0.95` | COCO 主指标，对定位最敏感 | 是 |
| `precision` | 在选定阈值下的精确率 | 是 |
| `recall` | 在选定阈值下的召回率 | 是 |
| `f1` | 精确率与召回率的调和平均 | 是 |
| `threshold` | 在 val 上选出的最佳置信度阈值 | 无绝对好坏 |
| `count_mae` | 每张图数鸟的平均绝对误差（只数，不看位置） | 越小越好 |
| `neg_fp_per_image` | 在没有鸟的负样本图上，平均误检几个框 | 越小越好 |
| `ms_per_image` | 每张图推理耗时（毫秒） | 越小越好 |
| `train_minutes` | 训练耗时（分钟） | 越小越省钱 |
| `mean_detections` | 平均每图输出框数 | 参考值 |

### 如何判断一个结果"好不好"

- `AP@0.5` < 0.1：基本不可用（传统方法常见）。
- 0.1 ~ 0.3：能找出一些鸟，但误检/漏检严重（HOG 常见）。
- 0.5 ~ 0.7：可用，但密集场景会漏。
- > 0.7：较好（YOLO 在这个数据集上通常能到 0.8 左右）。

### 为什么要看分尺寸/分密度

总体 AP 会掩盖问题。例如：

- 小目标 AP 很低 → 模型看不清小鸟 → 提高分辨率/切图。
- 密集场景召回低 → NMS 太狠或 max_det 太小 → 调 NMS/切图。
- 负样本 FP 高 → 模型把石头/浪花当鸟 → 加负样本/提高阈值/难负样本挖掘。

## 10. 对结果不满意？按症状调参

这一节是本文档最重要的部分。**先定位症状，再改对应的参数**，不要盲目乱调。

### 10.1 总体 mAP 偏低（但训练正常）

| 可能原因 | 怎么判断 | 可以改什么 | 预期效果 |
|---|---|---|---|
| 训练轮数不够 | 训练损失还在下降，val mAP 还在升 | `--epochs` 60→100 | mAP 上升，但时间变长 |
| 模型太小 | 大模型明显更好 | `yolov8n`→`yolov8s`/`yolov8m` | mAP 上升，速度下降 |
| 输入分辨率太低 | 小目标 AP 特别低 | `--imgsz` 512→640/960 | 小目标变好，显存/时间增加 |
| 数据增强不合适 | 训练集好、验证集差（过拟合） | `--aug strong`，或增加 `mixup` | 泛化变好 |
| 学习率不合适 | 损失震荡/不下降 | 在训练脚本里加 `lr0=0.001` 或 `0.02` | 收敛更稳 |
| 标注质量 | 框普遍偏大/偏小 | 检查 `annotation screenshot/` | — |

### 10.2 小目标漏检严重

这是本数据集最常见的失败模式（35% 的框面积 < 32² 像素）。

**按性价比排序：**

1. **提高推理分辨率**：`--imgsz 960`。鸟在输入里占的像素翻倍。
2. **切图推理**：`--tiles 2 --overlap 96`。把 512 切成 2×2，每块再放大，效果类似但更省显存。
3. **训练时用更高分辨率**：`04_train_yolo.py --imgsz 960`（需要更多显存，batch 要减小）。
4. **数据增强**：`--aug strong` 里的 `scale` 让目标随机变大变小。
5. **换更大的模型**：`yolov8s` 的特征分辨率更高。

> 注意：`imgsz` 必须是 32 的倍数（YOLO 的下采样要求），512、640、960 都可以。

### 10.3 密集鸟群漏检（一张图几十上百只）

| 调整 | 怎么改 | 原理 |
|---|---|---|
| 提高 NMS 阈值 | 推理 `--iou 0.7` | 避免相邻鸟的框互相抑制 |
| 提高最大检测数 | `--max-det 500` | 默认 300 在 130 只的图上够，但重叠框多时可能不够 |
| 切图 | `--tiles 2` | 每块里的鸟变少、变大，NMS 压力小 |
| 训练时 copy-paste | `--aug strong` | 人为制造密集场景 |
| 降低置信度阈值 | `--conf 0.001`（算 mAP 时） | 保留更多低分框 |

### 10.4 负样本（没有鸟的图）误检多

| 调整 | 怎么做 | 说明 |
|---|---|---|
| 提高部署阈值 | 推理/展示时 `conf` 0.25→0.5 | 最简单，但会牺牲召回 |
| 增加负样本 | 训练集里保留空 txt，不要删 | 本项目已有 154 张负样本 |
| 难负样本挖掘 | HOG：`--hard-neg 10000` | 把高分误检加入训练 |
| 数据增强 | `--aug strong` | 让模型见过更多礁石/浪花纹理 |
| 增大模型 | `yolov8s` | 容量大，更能区分相似纹理 |

### 10.5 框太大 / 一个小框套住好几只鸟

- **YOLO**：通常是 NMS 或训练标签问题。检查标注；推理时 `--iou 0.6`。
- **HOG**：调大 `--size-penalty`（0.4~0.6），让大窗口分数降低；
  同时保留较小的 `--sizes`（32,48,64）。代码里的 `containment_prune` 会自动删掉膨胀大框。
- **传统方法**：减小 `close_ksize`（5→3），避免形态学闭运算把相邻鸟粘在一起；
  启用分水岭变体 `multiscale_blackhat_ws`。

### 10.6 训练过拟合（训练集 mAP 高、验证集低）

| 调整 | 说明 |
|---|---|
| 增强 `--aug strong` | 最有效 |
| 早停 `--patience 10` | 自动停在验证集最好的轮次 |
| 减小模型 | `yolov8s`→`yolov8n` |
| 增加数据 | 作业允许只用部分数据，但全量通常更好 |
| 权重衰减 | 默认已有；可加 `weight_decay=0.001` |

### 10.7 训练欠拟合（训练集和验证集都低）

| 调整 | 说明 |
|---|---|
| 增加 `--epochs` | 先看损失曲线是否还在降 |
| 增大模型 | n→s→m |
| 提高学习率 | `lr0=0.02`（默认 auto 通常已经不错） |
| 检查数据 | 标签路径、类别名、图片是否能正常读取 |
| 关闭过强增强 | `--aug plain` 对比一下 |

### 10.8 速度太慢

| 场景 | 调整 | 代价 |
|---|---|---|
| YOLO 推理慢 | `--imgsz 512`、`--tiles 1`、关 TTA | 小目标变差 |
| YOLO 训练慢 | 减小 `--epochs`、`--batch` 不变但换 `yolov8n` | 精度下降 |
| HOG 慢 | `--stride 24`、减少 `--sizes`、`--score-threshold 0` | 召回下降 |
| 传统方法慢 | 减少 `se_sizes`、关闭分水岭 | 检测能力下降 |

### 10.9 显存不足（CUDA out of memory）

按顺序尝试：

1. `--batch` 减半（32→16→8→4）。
2. `--imgsz` 降到 512。
3. `--workers 2`（数据加载也占内存）。
4. 关闭其他占显存的程序。
5. 使用 `yolov8n` 而不是 `s/m`。
6. 仍然不行 → 用 Google Colab 免费 GPU，或只使用 50% 数据（作业允许）。

### 10.10 HOG 的专项调参

| 症状 | 调整 | 原理 |
|---|---|---|
| 小目标漏检 | `--stride 8`，`--sizes` 加 24,32 | 窗口更密、更小 |
| 大框套小目标 | `--size-penalty 0.5` | 抑制大窗口高分 |
| 误检多 | 训练时 `--hard-neg 10000`；推理 `score-threshold 0.5` | 更多难负样本 |
| 密集场景重复框 | `--nms 0.3` | 更激进的去重 |
| 训练太慢 | `--hard-neg 0`，`--neg-per-image 8` | 负样本减少 |
| 特征不够强 | `--feature hog_lbp` | 加纹理信息 |
| 分类器非线性 | `--classifier rf` | 但更慢、模型更大 |

### 10.11 传统方法的专项调参

参数都在 `src/classical.py` 的 `ClassicalParams` 里，改完重新跑 `02_run_classical.py`。

| 参数 | 作用 | 调大 | 调小 |
|---|---|---|---|
| `min_area` | 最小连通域面积 | 滤掉更多小噪声，但漏掉小鸟 | 保留更多小鸟，也更多噪声 |
| `max_area` | 最大面积 | 允许大鸟/大块 | 去掉礁石/岸线，但大鸟漏检 |
| `min_fill` | 最小填充率 | 只保留"实心"斑块，去掉细长浪花 | 保留更多形状，误检增加 |
| `max_aspect` | 最大长宽比 | 允许细长目标 | 去掉水平浪花/海岸线 |
| `resp_floor` | 响应阈值下限 | 更严格，误检少、漏检多 | 更宽松 |
| `otsu_scale` | Otsu 阈值系数 | >1 更严格 | <1 更宽松 |
| `se_sizes` | 结构元素尺寸 | 加入大尺寸检测大鸟 | 去掉大尺寸减少误检 |
| `close_ksize` | 闭运算核 | 填补空洞，但会把鸟粘在一起 | 保持鸟之间的分离 |
| `split_area` | 触发分水岭的最小面积 | 只拆大块 | 拆更多小块（可能过度分割） |
| `nms_iou` | 跨尺度合并 | 保留更多重叠框 | 删得更狠 |

## 11. 常见报错与解决办法

### 报错 1：`ModuleNotFoundError: No module named 'src'`

**原因**：没有在项目根目录运行，或者没有把根目录加入 `sys.path`。
**解决**：`cd` 到 `beach_bird_project` 再运行；脚本里已经写了 `sys.path.insert`，通常不会出现。

### 报错 2：`cv2 has no attribute 'HOGDescriptor'`

**原因**：安装了 OpenCV 5.x。
**解决**：
```powershell
pip install "opencv-python==4.12.0.88"
```

### 报错 3：`FileNotFoundError: ... images/val ...`

**原因**：数据集路径不对，或文件夹名不一致。
**解决**：确认 `data/Beach Bird Detection Dataset v1.0/images/val` 存在；
或修改 `src/common.py` 顶部的 `DATA_ROOT`。

### 报错 4：`CUDA out of memory`

见 10.9。先把 `--batch` 减半。

### 报错 5：`The process cannot access the file ...`（Windows）

**原因**：上一次训练还没完全退出，或者同时跑了两个训练。
**解决**：等几秒，或在任务管理器结束残留的 `python.exe`；不要并行跑多个 YOLO 训练。

### 报错 6：`SystemError: <built-in function LUT> returned a result with an exception set`

**原因**：内存不足时 OpenCV 的异常处理被打断（本项目在 16 GB 机器上同时跑 YOLO + HOG 时出现过）。
**解决**：不要同时跑多个重任务；关闭浏览器/其他程序；`--workers 2`。

### 报错 7：`numpy._core._exceptions._ArrayMemoryError`

**原因**：内存不足。HOG 评估时一次堆叠太多 patch。
**解决**：关闭其他程序；把 `WindowDetector` 里的 batch 从 2048 改成 512（在 `src/hog_svm.py` 中搜索 `2048`）。

### 报错 8：训练时 mAP 一直是 0

**原因**：
- 标签格式不对（不是 YOLO 归一化格式）；
- `dataset.yaml` 的 `nc`/`names` 不对；
- 图片和标签文件名不一致。
**解决**：先用 `00_explore_dataset.py` 检查能否读出框；打开 `annotation screenshot/` 对照。

### 报错 9：`Unsupported argument: ...`

**原因**：Ultralytics 版本差异，某些参数名不同。
**解决**：升级 `pip install -U ultralytics`，或删除脚本里不支持的参数。

## 12. 如何换成自己的数据

1. 按 YOLO 格式准备：
   ```
   my_dataset/images/train/*.jpg
   my_dataset/images/val/*.jpg
   my_dataset/labels/train/*.txt
   my_dataset/labels/val/*.txt
   ```
2. 新建 `my_dataset/dataset.yaml`：
   ```yaml
   path: /absolute/path/to/my_dataset
   train: images/train
   val: images/val
   nc: 1
   names:
     0: bird
   ```
3. 修改 `scripts/04_train_yolo.py` 里的 `DATA_ROOT`（或直接改 `src/common.py`）。
4. 传统方法和 HOG 的代码不用改，但**参数要重新调**（鸟的大小、背景复杂度都变了）。
5. 如果类别数 >1，需要把 `src/common.py` 的评估改成多类别（当前按单类别实现），
   YOLO 的 `nc/names` 也要相应修改。

## 13. 术语速查表

| 英文 | 中文 | 一句话解释 |
|---|---|---|
| bounding box | 边界框 | 框住目标的矩形 |
| IoU | 交并比 | 两个框的重叠程度，0~1 |
| TP / FP / FN | 真阳/假阳/假阴 | 框对 / 误检 / 漏检 |
| precision | 精确率 | 报出的框里有多少是真的 |
| recall | 召回率 | 真的鸟有多少被找到 |
| AP | 平均精度 | PR 曲线下面积 |
| mAP | 平均精度均值 | 多类别 AP 的平均；单类别时等于 AP |
| NMS | 非极大值抑制 | 合并重叠框 |
| HOG | 方向梯度直方图 | 描述边缘/形状的手工特征 |
| LBP | 局部二值模式 | 描述纹理的手工特征 |
| SVM | 支持向量机 | 找最大间隔超平面的分类器 |
| sliding window | 滑动窗口 | 在图上逐位置、逐尺度扫描 |
| hard negative mining | 难负样本挖掘 | 把高分误检加入负样本再训练 |
| data augmentation | 数据增强 | 随机变换训练图，提升泛化 |
| epoch | 训练轮 | 把所有训练图看一遍 |
| batch size | 批大小 | 一次送进模型的图片数 |
| learning rate | 学习率 | 每次参数更新的步长 |
| overfitting | 过拟合 | 训练集好、验证集差 |
| TTA | 测试时增强 | 推理时多变换几次再合并 |
| tiled inference | 切图推理 | 把大图切小块分别检测 |
| one-stage / two-stage | 单阶段/两阶段 | 直接回归框 vs 先出候选区域再分类 |

## 14. 完整复现命令清单

以下命令按顺序执行即可复现报告中的全部结果（假设已装好环境和数据）。

```powershell
# ---------- 0. 数据探索 ----------
python scripts/00_explore_dataset.py

# ---------- 1. 传统方法 ----------
python scripts/01_tune_classical.py --variant multiscale_blackhat --subset 120
python scripts/02_run_classical.py --variant all --split val  --use-best
python scripts/02_run_classical.py --variant all --split test --use-best

# ---------- 2. HOG + SVM ----------
# 主模型：HOG + LinearSVC + 难负样本
python scripts/03_train_hog_svm.py --name hog_linear --feature hog --classifier linear --hard-neg 6000
# 特征对比
python scripts/03_train_hog_svm.py --name hog_lbp_linear --feature hog_lbp --classifier linear --hard-neg 6000
# 分类器对比
python scripts/03_train_hog_svm.py --name hog_rf --classifier rf --hard-neg 6000
# 不做难负样本的基线
python scripts/03_train_hog_svm.py --name hog_no_hard --hard-neg 0

# 纯滑窗版本（用于对比/演示）
python scripts/03_run_hog_svm.py --name hog_linear --split val  --stride 16 --score-threshold 0 --box-shrink 1.0 --tag hog_linear
python scripts/03_run_hog_svm.py --name hog_linear --split test --stride 16 --score-threshold 0 --box-shrink 1.0 --tag hog_linear

# 推荐：传统候选框 + HOG 分类的级联版本（更快、更准）
python scripts/03_run_hog_proposals.py --model hog_linear     --split val --tag hog_prop
python scripts/03_run_hog_proposals.py --model hog_linear     --split test --tag hog_prop
python scripts/03_run_hog_proposals.py --model hog_lbp_linear --split val --tag hog_lbp_prop
python scripts/03_run_hog_proposals.py --model hog_lbp_linear --split test --tag hog_lbp_prop
python scripts/03_run_hog_proposals.py --model hog_rf         --split val --tag hog_rf_prop
python scripts/03_run_hog_proposals.py --model hog_rf         --split test --tag hog_rf_prop
python scripts/03_run_hog_proposals.py --model hog_no_hard    --split val --tag hog_nohard_prop

# 汇总 HOG 消融表
python scripts/03_make_hog_table.py

# ---------- 3. YOLO ----------
python scripts/04_train_yolo.py --model yolov8n.pt --name yolov8n_plain --epochs 60 --batch 32 --aug plain
python scripts/04_train_yolo.py --model yolov8n.pt --name yolov8n_aug   --epochs 60 --batch 32 --aug default
python scripts/04_train_yolo.py --model yolo11n.pt  --name yolo11n_aug  --epochs 60 --batch 32 --aug default
python scripts/04_train_yolo.py --model yolov8s.pt  --name yolov8s_aug  --epochs 60 --batch 16 --aug default
python scripts/04_train_yolo.py --model yolov8n.pt --name yolov8n_aug_960 --epochs 45 --batch 6 --imgsz 960 --aug default

# 每个模型都要在 val/test 上生成预测
foreach ($m in @("yolov8n_plain","yolov8n_aug","yolo11n_aug","yolov8s_aug","yolov8n_aug_960")) {
    python scripts/05_predict_yolo.py --weights "models/runs/$m/weights/best.pt" --name $m --split val
    python scripts/05_predict_yolo.py --weights "models/runs/$m/weights/best.pt" --name $m --split test
}

# 后处理实验（用最佳 YOLOv8n 权重）
python scripts/05_predict_yolo.py --weights models/runs/yolov8n_aug/weights/best.pt --name yolov8n_aug_tta  --split test --tta
python scripts/05_predict_yolo.py --weights models/runs/yolov8n_aug/weights/best.pt --name yolov8n_aug_tile2 --split test --tiles 2 --overlap 96 --imgsz 640

# ---------- 4. 统一评估 ----------
python scripts/06_evaluate_all.py
python scripts/06_model_info.py
python scripts/07_make_figures.py
```

> 注意：`03_run_hog_svm.py` 的 `--tag` 会决定输出文件名。
> 如果用了 `--tag hog_s16`，文件名是 `hog_hog_s16_test.json`，
> 需要在 `06_evaluate_all.py` 的 `METHODS` 列表里同步修改 `prefix`，否则会被跳过。
